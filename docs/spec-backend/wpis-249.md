# Wpis 249 — tworzenie zamówienia partnera w Selly

`POST /api/partnerzy/:id/zamowienia/:zamowienieId/utworz-w-selly` (requireAuth) → `{numerWlasny, idSelly}`; 403 (flaga `PARTNERZY_SELLY_ZAMOWIENIA` wyłączona), 404, 409 (blokady podglądu lub zmiana statusu w międzyczasie), 502 (odmowa Selly, komunikat bez sekretów), 503. Statusy zamówienia partnera: `przyjete` → `wysylanie` (zajęcie przed wywołaniem sklepu) → `wyslane` (+ `numer_wlasny` = `order_number` z odpowiedzi, a bez niego `order_id`); błąd sklepu przywraca `przyjete`. Gdyby proces padł po udanym wywołaniu, zamówienie zostaje w `wysylanie` — NIE wraca samo (człowiek sprawdza w Selly, zamiast ryzykować duplikat). Klient: `createOrder(body)` → `POST /api/orders`, w `METODY_ZAPISUJACE`. Pozycje: `selly_products.bridge_kod = products.kod` → `selly_product_id`/`selly_variant_id`. Ciało i blokady: `src/partnerzy/podglad-selly.ts`. Migracja 034 (ID Selly w `partnerzy`). Trasy poza `contract/openapi.yaml`.
