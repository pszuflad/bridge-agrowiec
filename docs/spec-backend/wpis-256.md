# Wpis 256 — tracking zamówień partnerów

Przesyłka (`partner_wysylki`, migracja 037) = numer listu przewozowego zamówienia partnera. `POST /api/partnerzy/:id/zamowienia/:zid/przesylki` (`{przewoznik, numerPrzesylki, typ?: "delivery"|"pickup", wyslano?, pozycje?: [{pozycjaId, ilosc}]}`; domyślnie wszystko, co jeszcze niewysłane) zapisuje przesyłkę i od razu plik trackingu: nazwa `tracking_<numer partnera>_<YYYYMMDD-HHmmss>_<id>.csv`, nagłówek `order_id;platform_order_id;supplier_item_id;ean;carrier;tracking_number;tracking_type;quantity_shipped;shipped_at`, linia na pozycję. Katalog partnera z `PARTNERZY_KATALOGI_TRACKINGU` (jak publikacja cenników: tylko `.env` produkcji, plik tymczasowy + rename, katalog musi istnieć). Błędy walidacji: 400/409; zamówienie obce lub nieistniejące 404. `plik_status`: `zapisany` | `brak_katalogu` | `blad` (+ `plik_blad`); `POST …/ponow` powtarza zapis. `GET …/plik` oddaje `{nazwa, tresc}` do podglądu w panelu. Format pliku to założenie użytkowniczki (brak wzoru od partnerów).
