# 262 — PARTNERZY: kurs EUR — NBP i ręczny równolegle, obowiązuje niższy

Decyzja użytkowniczki 2026-10-14: system ma jednocześnie liczyć kurs z NBP i uwzględniać kurs ręczny; przy każdym generowaniu bierze **korzystniejszy dla nas — niższy** („zgodnie z ochroną mojego interesu”). Uzasadnienie: cena w EUR = zakup / kurs, więc niższy kurs daje wyższą cenę w EUR — przy przeliczeniu EUR→PLN po realnym kursie nie ma straty (np. zakup 1000 zł: kurs 4,50 → 222 EUR, kurs 4,00 → 250 EUR; sprzedaż za 222 EUR przy realnym 4,00 oddaje ok. 889 zł).
Zmiana zachowania (jawna): dotąd kurs ręczny WYŁĄCZAŁ NBP (wybór źródła per kraj). Teraz `kursEur` zawsze próbuje NBP (zapisuje tabelę jako rezerwę) i, jeśli kraj ma kurs ręczny > 0, zwraca niższy z dwóch (remis: ręczny); gdy NBP nie odpowiada: ręczny vs ostatni zapisany NBP, a bez zapisanego — sam ręczny z ostrzeżeniem. Bez kursu ręcznego bez zmian (sam NBP). Pole `kursZrodlo` nie decyduje już o wyborze (zostaje w bazie i API dla zgodności; panel zawsze wysyła `nbp`); `kursZrodlo=reczny` bez wartości nie jest już błędem, tylko NBP. `kursReczny` jest zapisywany niezależnie od `kursZrodlo`, walidacja: liczba > 0 albo null.
Panel: zniknął wybór źródła; pole „Kurs ręczny (opcjonalny)”, kolumna „Używany kurs” pokazuje „NBP teraz … · ręczny … → obowiązuje niższy …”.
Skutek: kraje z kursem ręcznym ustawionym kiedyś jako jedyny (np. 4,50) zaczną zależeć od NBP, gdy ten spadnie poniżej. `partner_kursy.zrodlo` dostaje `reczny` (gdy ręczny wygrał/niedostępny NBP) albo `nbp`/`nbp-zapisany`.
